# Dracc  (Distributed registry and configuration center)

基于Raft算法实现(工程简化版)的分布式注册中心以及配置中心


## 特点

* 高可用,只支持集群部署
* 数据一致性:集群节点之间数据同步基于Raft核心思想，在正常网络环境和常规运维下提供强一致性
* 高性能(相比其他基于强一致性算法实现的产品)  
  节点间通信使用Netty长连接,避免频繁建连开销,线程模型设计尽量避免阻塞,代码细节注重性能    
  并且针对Raft日志复制路径做了深度优化：   
  日志文件采用追加写(append-only),并结合异步批量写入、未提交日志延迟删除、组提交(Group Commit,合并多次fsync)等策略,避免随机写和文件重写,显著提升写吞吐    
  本地三节点测试:写TPS>7500(SSD，120个线程共享一个客户端连接),读QPS>150k(100个线程共享一个客户端连接)。代码中有测试类,可拉取代码自行测试
* 数据持久化保存
* 对其他组件无依赖(比如数据库什么的)
* 原生支持分布式锁。不用自己在客户端封装,自带相对安全的高性能可重入分布式锁。(由于网络的不确定性,实现绝对安全的分布式锁是不可能的，还是需要业务方做好相应的判断以及处理)  
但是, 我觉得绝大部分场景下是完全没必要用分布式锁的,业务模块实现上最好能不用分布式锁就不用分布式锁。


## 主要功能
* 服务注册
* 服务发现
* 服务监听
* 健康检查
* 发布配置
* 获取配置
* 分布式锁
* ......

## 部署步骤
1、拉取代码  
2、项目根目录执行mvn clean package  
3、进入 dracc-server/target 目录  
4、找到dracc-server-1.0.tar.gz 压缩包,拷贝到需要实际部署的目录中  
5、解压压缩包(windows直接右键选择解压到当前目录,Linux执行 tar -zvxf dracc-server-1.0.tar.gz)  
6、进入解压出的config目录,编辑cluster.properties文件,配置这个raft集群的所有节点ip(需要配置本地节点ip、远端节点ip,配置文件中有例子)  
7、进入解压出的bin目录,执行启动脚本(run.sh或run.bat是前台运行,start.sh是后台运行),后台运行产生的日志会输出到解压出的log目录中。  
成功启动半数以上raft节点,则这个raft集群为可用状态,他会自动选举出leader,并对外提供服务。

## 设计说明（与标准 Raft 的差异）
本项目在实现上借鉴了Raft算法的核心思想（领导者选举、日志复制、安全性），但为了简化工程实现和提升性能，做了以下有意简化：    
1、日志条目未存储任期号：    
日志条目不存储任期号，选举时仅比较已提交索引和未提交日志数量。这依赖于日志连续无空洞。新Leader通过No-Op机制确保旧未提交日志在多数节点上确认后才提交，
未提交日志在降级时可能被丢弃，但此时对应的操作尚未向客户端返回成功，因此不会影响已经确认（已提交）的操作。    
2、心跳消息不携带任期:    
心跳消息不携带任期，任期同步通过连接建立时的RPC_SYNC_TERM消息以及收到更高任期的请求时被动更新。在正常网络环境下，该设计能正确工作。   
3、未持久化 votedFor    
节点重启后投票状态重置，但在同一任期内重复投票的概率极低，而且哪怕发生重复投票也不影响日志的安全性。    
4、日志压缩和快照策略简化
快照生成采用固定阈值，且快照与日志清理操作非原子，极端崩溃下可能需要人工恢复。    
这些简化使得代码更简洁、性能更高。在正常网络环境和常规运维下，系统能够提供强一致性和高可用性。
尽管实现与标准 Raft 协议存在一些细节差异，但这些差异在正常运行条件下不会影响数据的安全性；
